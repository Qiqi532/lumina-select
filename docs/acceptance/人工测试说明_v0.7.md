# 光影选片助手 · 人工测试说明（v0.7 / M1）

> 面向作者本人的**手动验收手册**。目标：用最少的时间，验证本期全部改动在**真实使用路径**上确实成立；
> 同时产出 **T-17 人脸评测所需素材**。
>
> 本清单用于当前开发候选包的人工复核；执行时填写实际 HEAD、日期和环境，不沿用历史测试结论。
> 预计总耗时：**首次完整跑完约 60–90 分钟**（含分析等待）；熟练后复跑约 25 分钟。
> 本文档为普通工作区文件，可随意修改勾选。

## 0. 测试前的准备（10 分钟，只做一次）

### 0.1 选择运行形态

| 形态 | 启动方式 | 适用 |
|---|---|---|
| **A. 源码态（推荐先跑这个）** | 在仓库根目录运行 `.\.venv\Scripts\python.exe app_qt.py` | 便于看日志、出错好定位 |

> **建议：先做 A 组（1–9 项），全通过后再做 B 组（第 10 项）**。B 组失败通常只是打包漏带文件，与逻辑无关。

### 0.2 准备素材

准备 **3 个目录**（不要用同一批照片凑数）：

| 目录 | 建议内容 | 用途 |
|---|---|---|
| `项目A` | 一次真实拍摄（含同场景连拍 5–10 组） | 主流程 + 分面筛选 |
| `项目B` | 不同相机/镜头拍的（有别于 A 的 EXIF） | 验证分面计数跨项目正确 |
| `项目C` | **人像为主，含 ≥5 个人**，其中至少 2 人有：正脸清晰 / 侧脸 / 闭眼 各一张 | 人脸功能 + T-17 素材 |

## 3. 分面筛选条（本次新增重点，10 分钟）

| # | 操作 | 预期结果 |
|---|---|---|
| 3.1 | 复核页左侧出现**筛选侧栏**，含「相机型号 / 镜头 / 焦距 / 光圈 / ISO / 星级 / 标签 / 场景」分面 | 每个分面可展开，取值后带**计数** |
| 3.2 | 展开「相机型号」 | 计数与实际相符（可先只放 项目A 的照片核对） |
| 3.3 | 点选「相机型号 = 某个值」 | 队列**立即**刷新（应 < 0.3 s，无卡顿），该 chip 高亮 |
| 3.4 | **再点一个「焦距」分段**（如「长焦 >135mm」） | **两个条件同时生效**（AND），计数正确 |
| 3.5 | 观察其他分面的计数 | 它们应**随已选条件变化**（这是分面检索语义），但**自身分面的计数不应被自己筛没** |
| 3.6 | 点已选中的 chip | 取消该条件，队列恢复 |
| 3.7 | 把某分面筛到**某取值计数变为 0** | 该取值 chip 应**变灰且不可点** |
| 3.8 | 先选中一个值，再叠加别的条件使该值计数降到 0 | ⚠️ **该 chip 仍应可点（能取消）** —— 这是本期修的 bug |
| 3.9 | 点「清除全部筛选」/「全部」预设 | 分面与预设**互相清空**，不交叉残留 |
| 3.10 | 切换星级阈值（如「≥3 星」）后看分面 | 计数与队列一致 |

> **已知易错点**：3.4 中的「长焦」是**分段桶**（不是等于某个焦距数字）。若曾出现「选了长焦结果 0 条」，那是本期已修复的问题；如仍复现请立即报告。

## 4. 批量操作与任务取消（10 分钟）

| # | 操作 | 预期结果 |
|---|---|---|
| 4.1 | 框选/多选一批照片 → 批量标星、批量标保留(P)/排除(X) | 一次生效；**支持撤销**（Ctrl+Z 或撤销按钮） |

| 4.5 | 取消后再次点「开始分析」 | 可重新跑，结果覆盖/续算正确 |

> ⭐ **4.3 是本期最重要的验收点之一**（「取消是协议不是中断」）。若取消后人工决策丢失，属**严重缺陷**。

## 10. T-17 人脸评测素材清单（重要）

T-17（人脸识别 / 归类 / 按人检索）是 **M2 阶段的核心任务**，但它需要**真实人像材料**才能做有效评测。
请在跑第 5 组时顺手收集，**不必额外拍摄**。

### 10.1 最低素材要求

| 项 | 要求 | 为什么 |
|---|---|---|
| 项目数 | **≥ 3 个**不同拍摄场景（如：家庭聚会 / 户外活动 / 棚拍） | 验证跨场景泛化 |
| 照片总数 | **≥ 200 张** | 统计才有意义 |
| 人数 | **≥ 10 个不同的人** | 验证多人区分（不是只认一个人） |
| 每人照片数 | 每人 **≥ 5 张**，尽量跨不同日期/角度 | 验证同一人的稳定性 |

### 10.2 素材要覆盖的「难例」（各至少 1 例）

> 这些是最能暴露模型缺陷的场景，**必须包含**：

| 难例类型 | 具体说明 | 想验证什么 |
|---|---|---|
| **正脸清晰** | 单人正面、光照良好 | 基线：应该能认对 |
| **侧脸 / 半侧** | 转动 45°–90° | 姿态鲁棒性 |
| **闭眼** | 眨眼瞬间 | 会不会影响识别 |
| **戴眼镜 / 墨镜** | 普通眼镜 + 墨镜 | 遮挡鲁棒性 |
| **戴口罩 / 手挡脸** | 如有 | 遮挡鲁棒性 |
| **背影 / 完全不露脸** | 同一人的背影照 | **不应被识别成某人**（假阳性检验） |
| **同卵双胞胎 / 长相相似的人**（如有） | 家族照常见 | 区分能力上限 |
| **低光 / 逆光 / 过曝** | 光线恶劣 | 画质退化影响 |
| **远景小人脸** | 人脸占画面 < 2% | 小目标检出率 |
| **同框多人（≥5 人）** | 合影 | 多人同时检出 |
| **跨年龄**（如有） | 同一人 5 年前后的照片 | 长期稳定性 |

### 10.3 提供给「评测标准答案」的方式（重要）

T-17 要算准确率，就**必须有一份人工标注的「正确答案」**。两种方式二选一：

**方式 A（推荐，省事）**：在素材目录里做**分文件夹 + 命名约定**：

```
项目A_人脸评测/
  person_01_张三/
    zhangsan_front_01.jpg      ← 正脸
    zhangsan_side_01.jpg       ← 侧脸
    zhangsan_glasses_01.jpg    ← 戴眼镜
  person_02_李四/
    ...
  unlabeled/                    ← 不确定 / 不属于任何人的
    crowd_01.jpg
```

> 文件夹名 = 真值身份。我据此自动生成评测标注，**你不用写任何表格**。

**方式 B**：给一份 CSV（文件名 → 身份），但**不如下拉文件夹直观**，且容易和照片对不上。

## 附：常见问题速查

| 现象 | 说明 |
|---|---|
| 首次分析很慢 | 首次要加载模型（数百 MB）+ 建缩略图缓存；二次访问会快很多（缓存命中 0.12 s 级） |
| 日志里出现 `degradations` | 离线降级记录，**设计行为**，不是错误 |
| 无 GPU 时特别慢 | CPU 推理约为 GPU 的 4–8 倍；属正常 |
| 杀软误报 | PyInstaller 打包产物常见；可加白名单，非本项目问题 |
| 关闭程序时提示有任务 | 程序会请求取消正在跑的任务后再退出，属正常保护 |
